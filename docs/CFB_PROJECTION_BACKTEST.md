# CFB Projection Backtesting

The production matchup projection now has a full-chain historical evaluator.

## Core rule

A historical prediction must be generated by the same
`sports_aggregator.cfb.game_projection.project_matchup()` function used by the
live site, with the historical game's kickoff passed as `as_of_date`.

No actual from the game being projected may enter its own trailing snapshot.

## xPoints model folds

The persisted production xPoints model must **not** be loaded blindly during a
historical backtest. The current production model may have been trained on data
that occurs after the historical game.

`projection_backtest.build()` therefore freezes one in-memory points model per
test season:

- 2023 games: train through 2022
- 2024 games: train through 2023
- 2025 games: train through 2024
- 2026 games: train through 2025

The default training floor is 2022. If a fold has too little eligible history,
the projection uses the production adapter's simpler matchup/league fallback.

## Build historical predictions

```bash
python -m sports_aggregator.cfb.projection_backtest_cli run \
  --from-year 2022 \
  --to-year 2025
```

For a single season:

```bash
python -m sports_aggregator.cfb.projection_backtest_cli run --year 2025
```

## Report

```bash
python -m sports_aggregator.cfb.projection_backtest_cli report \
  --from-year 2025 \
  --to-year 2025
```

The report includes MAE, RMSE and signed bias for:

- offensive points
- scoreboard points (diagnostic; defensive/special-teams scores are not modeled)
- total, pass and rush yards
- drives and plays
- dropbacks and rush attempts
- points per drive
- giveaways
- red-zone trips and red-zone touchdowns

Game-level output includes:

- projected score total
- projected score margin
- projected offensive total
- stored-market total benchmark
- stored-market margin benchmark

Diagnostics are also grouped by:

- season
- week band
- amount of prior team history
- absolute opponent-quality edge
- number of quality sources available

## Important interpretation

`projected_offensive_points` is an offensive-drive forecast. A final scoreboard
score can include defensive and special-teams touchdowns. The backtest stores
both `actual_offensive_points` and `actual_score_points` so model error and
user-facing score error can be evaluated separately instead of conflated.

The market comparison is a benchmark, not a claim of betting edge.
